# P0-11 — PostgreSQL deployment

Status: todo · Phase: 0 · Depends on: P0-01 · Parallel-safe with: P0-02, P0-04 · Size: M

## Goal
A reproducible, documented deployment of PostgreSQL 17 for EBS: primary + streaming hot standby,
pgBackRest backups with point-in-time recovery, PgBouncer pooling — as Compose files and an Ansible role.

## Read first
- docs/architecture.md § "Roadmap and tech stack" → Service bullet

## Scope (files)
- create `deploy/postgres/compose.yaml` (primary, standby, pgbouncer, pgbackrest repo volume),
  `deploy/postgres/conf/*` (postgresql.conf fragments, pg_hba.conf, pgbouncer.ini, pgbackrest.conf)
- create `deploy/ansible/roles/ebs_postgres/` (tasks, templates, defaults, handlers, molecule scenario)
- create `deploy/postgres/README.md` (install, failover, restore runbook)
- create `tests/deploy/test_compose.sh` and `tests/deploy/test_backup_restore.sh`, wired as a manual
  CI job `deploy-smoke`

## Out of scope
Schema/migrations (P0-10). HA automation (Patroni) — documented as a later option, not built.

## Requirements
- R1 `docker compose up` (or `podman compose`) yields a primary accepting connections through PgBouncer
  (transaction pooling) and a standby in streaming replication (`pg_stat_replication` shows it).
- R2 Secrets are never committed: passwords come from env files listed in `.gitignore` with a
  `.env.example`; pg_hba requires scram-sha-256; TLS enabled with self-signed certs generated by a script.
- R3 pgBackRest: full backup + WAL archiving configured; `test_backup_restore.sh` writes rows, takes a
  backup, writes more rows, restores to a timestamp between them, and checks the row set (PITR).
- R4 Failover runbook: manual promotion of the standby documented and exercised by `test_compose.sh`
  (promote, reconnect via PgBouncer after config switch).
- R5 Ansible role is idempotent (second run reports `changed=0`) under molecule with a container driver.
- R6 Settings suitable for ~100 users + CI: `max_connections` small (100) behind PgBouncer
  (`default_pool_size` 20), `idle_in_transaction_session_timeout` 60 s, `statement_timeout` for the
  `ebs` role 30 s.

Versioning works like software packages, in three layers:

| Object | Mutable? | What it is |
| --- | --- | --- |
| **Build** | no | One run of a flow: its plan, results, timings, who ran it. |
| **Release** | no (it can be *yanked*, never deleted) | A name and version (`rtl-team/cpu 2026.09.3`) for selected outputs of one build, by digest, with notes. |
| **Channel** | yes, with full history | A pointer such as `rtl-team/cpu:stable` to one release, optionally guarded by a gate build. |

## Why three layers

- Builds are cheap and frequent; most are never released.
- A release is a decision a team takes and can explain: which build, which outputs, why.
  Because it records digests, the bytes are exactly the ones that were tested, and the CAS
  keeps them as long as the release exists.
- A channel lets consumers follow `stable` without editing anything, while the producing team
  decides when `stable` moves. A gate (`[release.gates]`) can require a passing build of a
  given project for that release first.

## Teams work asynchronously

A downstream team (verification, DfT, backend) imports a release by channel in its flow
(`imports:`), and `ebs lock update` pins the exact release in a `flow.lock` committed to git.
Builds only ever use the pinned release: moving `stable` changes nothing downstream until the
consuming team updates its lock, so each team upgrades on its own schedule. `ebs lock check`
(exit 1) tells CI that an update is waiting.

Every build records which releases it imported and every action records which inputs made
which outputs. That is what [provenance queries](/ebs/guides/provenance/) walk: `ebs why`,
`ebs used-by` and `ebs tests` ("which tests ran on the RTL behind this netlist").

## Across domains

Releases live in the [domain](/ebs/concepts/domains/) of the build they come from. Sharing with
another NDA scope is an explicit, audited copy, `ebs release export --to <domain>`, which needs
membership in both domains and never links objects across them.

Try it: [Publish a release](/ebs/tutorials/releases/).

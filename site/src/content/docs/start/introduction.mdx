EBS (the EDA Build System) runs EDA flows (RTL lint, compilation and regressions today,
synthesis and implementation later) as a graph of **actions**. Each action is identified by a
digest of everything that can change its result. If the digest has been built before, by
you, a colleague or CI, the result is reused instead of recomputed.

You describe the flow in YAML. Existing Makefiles and Tcl scripts can be wrapped as they are,
and EBS takes care of the parts a Makefile does not: content hashing, a shared cache, SLURM
licenses, team releases and provenance.

## What changes compared to Make

| | Make | EBS |
| --- | --- | --- |
| Decides to rerun by | file timestamps | content digests of inputs, params, tools and env |
| Fresh checkout (CI, new clone) | rebuilds everything | reuses every result already in the shared cache |
| Comment-only RTL change | reruns everything downstream | reruns the one action; stops where outputs are identical (early cutoff) |
| Tool upgrade | invisible unless you `make clean` | the toolchain id changes, so dependent actions rerun |
| Results shared between users | no | yes, scoped by NDA domain |
| Know what produced an artifact | no | every build stores its full plan: params, input digests, toolchains |
| Licenses on the grid | job starts, then waits for a license | the job is queued until SLURM has the license |

## When to use it

EBS pays off when the same work is run many times by many people: regressions, lint across
blocks, nightly CI, or several teams consuming each other's outputs. For a one-person
experiment that runs once, a Makefile is simpler.

# EBS documentation site

Astro + Starlight, deployed to GitHub Pages by `.github/workflows/site.yml`
(<https://mouettesylvain-spec.github.io/ebs/>). Node version: `.nvmrc`.

```sh
make site-dev      # http://localhost:4321/ebs/ with live reload (regenerates the reference first)
make site-build    # what CI runs: reference + astro check + build + link validation
make site-bench    # remeasure the landing page numbers (needs EBS_TEST_PG_URL)
```

## How the site stays true to the code

| Content | Source of truth | Mechanism |
| --- | --- | --- |
| `src/content/docs/reference/**` | CLI, rule and toolchain modules, flow schema, design docs, task index | Generated by `scripts/gen_site_reference.py` before every dev/build; gitignored. Never edit it: edit docstrings, help texts or the design docs. |
| Code shown on pages | The repository files | `<RepoFile path="…" />` reads the file at build time; a missing file fails the build. |
| Operate pages | `deploy/*/README.md` | `<RepoDoc path="…" />` renders the README itself. |
| Tutorials and quickstart | The CLI's real behaviour | Every `console` block under `start/` and `tutorials/` is executed by `tests/e2e/test_docs.py`. |
| `flow.yaml` snippets | The flow schema and model | A block titled `…flow.yaml` is validated by `tests/unit/docs/test_site_snippets.py`. |
| Landing page numbers | The examples | `src/data/bench.json`, written by `scripts/site_bench.py`, regenerated on every deploy. |
| Links | | `starlight-links-validator` fails the build on a broken internal link. |

## Layout

```
astro.config.mjs        Starlight config, sidebar groups (one per content directory)
site.config.json        base path, site URL, repo URL (shared with the Python generator)
src/content/docs/       pages; sidebar order = `sidebar.order` frontmatter
  index.mdx             landing page (splash template; hero rendered by components/landing/Hero.astro)
src/components/         RepoFile, RepoDoc, landing/*
src/scenes/<name>/      one animation: <Name>Scene.astro (SVG in its final state) + <name>.ts (timeline)
src/scenes/_lib/        SceneFrame.astro (frame, caption, replay) and scene.ts (play on scroll,
                        pause off screen, reduced motion = final frame)
src/styles/tokens.css   every colour, size, radius and duration; starlight.css maps Starlight onto it
src/lib/repo.ts         repository paths and URLs
```

## Adding things

- **A page**: an `.md`/`.mdx` file in the right directory with `title`, `description` and
  `sidebar.order`. Links are absolute with the base: `/ebs/guides/debugging/`.
- **A tested tutorial**: put it under `tutorials/` and write commands in `console` blocks
  (`$ command`, then expected output lines, `…` for variable text). Each page runs on a fresh
  copy of `examples/` and a fresh database.
- **A scene**: copy an existing `src/scenes/<name>/` folder. Draw the SVG in its *final* state
  with the shared classes (`box`, `label`, `sub`, `mono`, `wire`, `dot`, `tag-*`); in the
  builder, `set` the start state, then animate towards the final one with the site timeline.
  Readers without JavaScript or with reduced motion see the SVG as drawn.
- **A colour or size**: add a token in `tokens.css`; components never hard-code colours.
